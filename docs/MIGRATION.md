# Notion migration gate

No production records have been imported yet. The signed-in sample established that RMs, review pages, inline comment threads and attachments must all be captured. A gallery export alone is not sufficient.

Keep the captured snapshot in `import-private/` (ignored by Git). Workspace export is disabled and the owner will not be contacted; do not try to re-enable export, change workspace sharing, or otherwise work around that restriction. The four initiatives are transcribed by hand from pages already viewable to the signed-in account, using an authorized connection or signed-in browser only. Read every nested block and paginate records and comments; preserve source page IDs and permalinks, timestamps, attribution and reply relationships; save each attachment as a real local file (expiring URLs do not count as retained). Treat the manual copy as provisional: it is not complete until the `expectedCounts` inventory has been built for every kind and `check-import.mjs` reports no gaps.

Before production import, run `node scripts/check-import.mjs ../import-private/manifest.json` from `app/`. The manifest is a JSON object with `capturedAt` (ISO-8601), `sourceWorkspace`, a mandatory `expectedCounts` inventory (one non-negative integer per supported kind — declare `0` for kinds with nothing captured) and a non-empty `records` array. Every record needs `kind` (one of: initiative, rm, review, thread, comment, attachment, person), a unique non-empty string `sourceId`, an http(s) `sourceUrl`, and `complete: true`. Children (`rm`, `review`, `thread`, `comment`, `attachment`) need a `parentSourceId` that resolves to a record of an allowed parent kind — `rm`→initiative, `review`→rm, `thread`→rm|review, `comment`→thread|comment, `attachment`→initiative|rm|review|thread|comment — with no parent cycles; `initiative` and `person` take no parent. Authored records (`rm`, `review`, `comment`) need an `authorSourceId` that resolves to a `person` record, or an explicit `authorUnresolved: true`. Threads need a non-empty string `quote` or `blockSourceId` (an object or other non-string value does not count), or an explicit `anchorUnresolved: true`. Attachments must set `localPath` to a real regular file that resolves inside the manifest's own directory (no absolute paths, no `..`, no symlink leaving the directory); a `durableUrl` may be recorded for context but never substitutes for a retained local copy. Content may be stored alongside each record, but do not put credentials in the manifest.

`expectedCounts` must declare every supported kind explicitly, including `0`, so a kind left out of both the records and the inventory (e.g. comments or attachments that were never captured) is still caught. The gate fails closed on a malformed manifest, a missing or non-object inventory, a missing per-kind entry, unknown or non-integer counts, count mismatches, bad field types (including a non-string `quote`/`blockSourceId`, which never counts as a recovered anchor), records whose `kind` is not a supported value, dangling or wrongly-typed parents and authors, parent cycles, and unretained or directory-escaping attachments; it never guesses an author or a comment anchor. The report is JSON `{ status, counts, warnings, unresolved, errors }` on stdout: `BLOCKED` (exit 1) whenever `errors` is non-empty, `READY_WITH_UNRESOLVED` (exit 0) when the only outstanding items are explicitly-flagged `unresolved` authors/anchors a human must still map, otherwise `READY_FOR_MAPPING` (exit 0). `node scripts/check-import.test.mjs` exercises the gate with synthetic corruption, path-escape, retention and relationship fixtures.

Resolve missing parents and incomplete captures before mapping into relational tables. Preserve unmatched people as historical identities; do not create approved accounts or match by display name. People who cannot be matched and comment anchors that cannot be recovered stay explicitly marked (`authorUnresolved` / `anchorUnresolved`) and are carried through as unresolved — never inferred or fabricated. Historical timestamps are not evidence of original deadlines, and missing submission versions cannot be reconstructed. Keep old HP as metadata; approved opening balances are 100. Never evaluate historical obligations for new penalties.

The final relational import must run in staging first, in a transaction with unique source IDs, then compare source and destination counts and relationships.
