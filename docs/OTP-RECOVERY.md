# Open Labs email sign-in recovery

The 2026-09-22 live attempt logged `POST /otp` at 17:37:18, successful `GET /verify` login at 17:37:23, and `GET /user` 200 at 17:37:24. Later `/verify` requests at 17:37:32 and 17:38:21 returned `403 One-time token not found`. The link is one-time use. The first visible page was the app's generic "Nothing here" route, and no `sb-...-auth-token` entry remained in Chrome local storage afterward. The exact reason the successful verification did not leave a durable browser session remains unproven; do not attribute it to a scanner without a controlled test.

The app now recognizes Supabase error fragments and offers a retry path. It also has an optional six-digit email code form for returning members using `verifyOtp({ email, token, type: 'email' })`. The code form only works after the hosted Supabase **Magic Link** email template includes `{{ .Token }}`. The repository's `supabase/email-templates/magic-link-code.html` is the exact candidate content. Hosted Supabase templates are not deployed by GitHub Pages or SQL migrations; an operator must apply this template in Supabase Dashboard > Authentication > Email Templates > Magic Link, with a subject such as "Your Open Labs sign-in code". Keep a copy of the old template until the controlled test passes. The sign-in request still uses `signInWithOtp` and does not require a separate endpoint.

Controlled test after applying the template: request one email for an existing test account, enter its six-digit code in the same browser without opening a confirmation link, and confirm the member screen appears. Then reload the clean site URL and confirm the session remains. Confirm a `sb-...-auth-token` key is present by key name only, never record its value. Finally sign out and confirm it disappears. If code verification succeeds but the app still shows Sign in, inspect the account's `public.profiles` row and the browser console/network error for `loadLive`; do not keep requesting codes.

The `Confirm Signup` template for new accounts is separate and is not changed by this recovery. Test returning-account sign-in first. Do not announce code sign-in as live until the hosted template has been applied and verified. The magic link can remain available until then.
